# BBW Dashboard Enhancements - Requirements & Solutions

## Executive Summary

This document addresses critical gaps in the current BBW Dashboard implementation and provides solutions for enhanced functionality, data accuracy, and user experience improvements.

## Current Issues Analysis

### F1: TREND Column Confusion
**Problem**: TREND column changes based on 5-minute candles, causing confusion about whether it represents trend/periods which I need or long-term trends/periods.

**Root Cause**: 
- `determineBBWTrend()` uses only 6 candles (30 minutes) for trend calculation
- No distinction between that last 6 candle from T time vs the candles which I require to analyze. 
- Trend calculation is too sensitive to recent price movements
- lets say there were a period of 4 candles that were insde the bb width threshold range from 12:20 - 12:40 PM. Once its past 12:40PM, there is no way to keep track of those 4 candle analysis as the current bbw and range value changes as time moves. 

**Impact**: Users cannot distinguish between what important happened vs what is going on now. 

### F2: Missing Historical Analysis
**Problem**: No persistent storage of live analysis results, making it impossible to retain insights.
I need to track more parameters per candle and make sure they are recalculated for every candle 
1. Count of number of consecutive candles that were in the threshold range. There can be multiple series of consecutive candles in the lowest bb width threshold range in a single day itself. 
2. range_entry_time when the 1st candle entered in the lowest bb width threshold.
3. range_exit_time when last candle was present in lowest bb width threshold

**Root Cause**:
- All analysis is calculated on-the-fly without persistence
- No database storage for historical analysis results in the same day.
- No separation between current and what happened just before in the same day analysis
- No tracking of multiple range series within a single trading day
- No persistence of range entry/exit times and duration

**Impact**: Valuable insights are lost between sessions, reducing trading effectiveness.

### Phase 1: Enhanced Range Series Tracking (Week 1)

#### 1.1 Enhanced BBWidthMonitorService Implementation
**Priority**: Critical
**Effort**: 3 days

**Solution**: Implement comprehensive range series tracking in BBWidthMonitorService

**Enhanced ProcessBBWidth Method**:
```go
// Add to BBWidthMonitorService struct
type BBWidthMonitorService struct {
    // ... existing fields
    rangeTrackers map[string]*RangeTracker // Track per instrument
    rangeMutex    sync.RWMutex
}

type RangeTracker struct {
    currentSeriesID    int
    inRange            bool
    entryTime          *time.Time
    consecutiveCount   int
    lastCandleTime     time.Time
}

// Enhanced ProcessBBWidth method
func (s *BBWidthMonitorService) ProcessBBWidth(
    ctx context.Context,
    instrumentKey string,
    candle domain.AggregatedCandle,
    bbWidthHistory []domain.IndicatorValue,
    stockMeta response.StockGroupStockDTO,
) error {
    bbWidth := candle.BBWidth
    if bbWidth <= 0 {
        return nil
    }

    // Get historical minimum and range
    lowestMinBBWidth, err := s.getLowestMinBBWidth(ctx, instrumentKey)
    if err != nil {
        return fmt.Errorf("failed to get lowest min BB width: %w", err)
    }

    minRange, maxRange := s.calculateBBWidthRange(lowestMinBBWidth)
    inRange := bbWidth >= minRange && bbWidth <= maxRange

    // Track range series
    s.trackRangeSeries(ctx, instrumentKey, candle, inRange, lowestMinBBWidth)

    // Existing pattern detection logic
    if len(bbWidthHistory) >= 3 && s.isContractingPattern(bbWidthHistory) {
        if inRange {
            log.Info("[BB Monitor] BB Range Alert: %s - %d consecutive contracting candles in optimal range",
                instrumentKey, len(bbWidthHistory))
            return s.triggerBBRangeAlert(ctx, stockMeta, bbWidth, lowestMinBBWidth, len(bbWidthHistory))
        }
    }

    return nil
}

// New method to track range series
func (s *BBWidthMonitorService) trackRangeSeries(
    ctx context.Context, 
    instrumentKey string, 
    candle domain.AggregatedCandle, 
    inRange bool,
    lowestMinBBWidth float64,
) {
    s.rangeMutex.Lock()
    defer s.rangeMutex.Unlock()

    tracker, exists := s.rangeTrackers[instrumentKey]
    if !exists {
        tracker = &RangeTracker{}
        s.rangeTrackers[instrumentKey] = tracker
    }

    if inRange && !tracker.inRange {
        // New range series started
        tracker.currentSeriesID++
        tracker.entryTime = &candle.Timestamp
        tracker.consecutiveCount = 1
        tracker.inRange = true
        
        log.Info("[Range Tracker] New range series started for %s: SeriesID=%d, EntryTime=%v", 
            instrumentKey, tracker.currentSeriesID, candle.Timestamp)
            
    } else if inRange && tracker.inRange {
        // Continuing range series
        tracker.consecutiveCount++
        
    } else if !inRange && tracker.inRange {
        // Range series ended
        exitTime := candle.Timestamp
        duration := exitTime.Sub(*tracker.entryTime).Minutes()
        
        // Persist range series data
        s.persistRangeSeries(ctx, instrumentKey, tracker, exitTime, duration, lowestMinBBWidth)
        
        // Reset tracker
        tracker.inRange = false
        tracker.entryTime = nil
        tracker.consecutiveCount = 0
        
        log.Info("[Range Tracker] Range series ended for %s: SeriesID=%d, Duration=%.1f min, Count=%d", 
            instrumentKey, tracker.currentSeriesID, duration, tracker.consecutiveCount)
    }
    
    tracker.lastCandleTime = candle.Timestamp
}

// Persist range series to database
func (s *BBWidthMonitorService) persistRangeSeries(
    ctx context.Context,
    instrumentKey string,
    tracker *RangeTracker,
    exitTime time.Time,
    duration float64,
    lowestMinBBWidth float64,
) {
    // Update the latest candle with range series data
    err := s.candle5MinRepo.UpdateRangeSeriesData(ctx, instrumentKey, &domain.RangeSeriesData{
        SeriesID:           tracker.currentSeriesID,
        EntryTime:          *tracker.entryTime,
        ExitTime:           exitTime,
        DurationMinutes:    int(duration),
        ConsecutiveCount:   tracker.consecutiveCount,
        LowestMinBBWidth:   lowestMinBBWidth,
    })
    
    if err != nil {
        log.Error("[Range Tracker] Failed to persist range series for %s: %v", instrumentKey, err)
    }
}
```

// Add to Candle5MinRepository interface
type Candle5MinRepository interface {
    // ... existing methods ...
    UpdateRangeSeriesData(ctx context.Context, instrumentKey string, rangeData *domain.RangeSeriesData) error
    GetLatestCandleWithRangeData(ctx context.Context, instrumentKey string) (*domain.Candle5Min, error)
}

// Implementation in postgres/candle_5min_repository.go
func (r *Candle5MinRepository) UpdateRangeSeriesData(ctx context.Context, instrumentKey string, rangeData *domain.RangeSeriesData) error {
    // Update the latest candle with range series data
    updateResult := r.db.WithContext(ctx).
        Table("stock_candle_data_5min").
        Where("instrument_key = ? AND timestamp = (SELECT MAX(timestamp) FROM stock_candle_data_5min WHERE instrument_key = ?)", 
            instrumentKey, instrumentKey).
        Updates(map[string]interface{}{
            "range_series_id":           rangeData.SeriesID,
            "range_entry_time":          rangeData.EntryTime,
            "range_exit_time":           rangeData.ExitTime,
            "range_duration_minutes":    rangeData.DurationMinutes,
            "range_consecutive_count":   rangeData.ConsecutiveCount,
        })

    if updateResult.Error != nil {
        return fmt.Errorf("failed to update range series data: %w", updateResult.Error)
    }

    return nil
}

## Key Benefits of Enhanced Solution

1. **Real-time Range Tracking**: Every 5-minute candle is processed and range series are tracked automatically
2. **Multiple Series Support**: Each consecutive range gets unique series ID, supporting multiple squeeze opportunities per day
3. **Precise Timing**: Entry/exit times and duration for each range series
4. **Performance Optimization**: BBWDashboardService uses persisted data instead of recalculating
5. **Historical Analysis**: Complete range series history preserved in database
6. **Data Consistency**: Single source of truth for range calculations in BBWidthMonitorService
