The Setbull Trader system currently operates in **HYBRID MODE** with both V1 (legacy) and V2 (new) systems running concurrently. This document provides a detailed analysis of both systems, their integration points, and the complete V2 internal flow using class names and methods.

## 1. V1 vs V2 System Comparison

### V1 System (Legacy) - Time-Based Trading Execution

**🎯 Primary Purpose**: Execute actual trades at specific market times

**⏰ Trigger Mechanism**: 
- Specific time-based triggers (9:15 AM, 1:00 PM)
- Only activates at predefined market times

**💼 Execution Type**: 
- Real trading with order placement
- Creates trade parameters, execution plans, and places orders

**📊 Data Source**: 
- Backtest analysis files
- Historical performance data
- Pre-calculated trading metadata

**🔄 Processing Flow**:
```
Time Trigger → Group Execution → Stock Processing → Trade Parameters → Execution Plan → Order Placement
```

**🏗️ Core Classes and Methods**:
- `GroupExecutionScheduler.TriggerGroupExecution()` - Main orchestrator
- `GroupExecutionService.ExecuteDetailedGroup()` - Detailed execution logic
- `TradeParametersService.CreateTradeParameters()` - Trade parameter creation
- `ExecutionPlanService.CreateExecutionPlan()` - Execution plan generation
- `OrderExecutionService.ExecuteOrders()` - Actual order placement

**📈 Output**: Real trading orders sent to broker

---

### V2 System (New) - Real-Time Strategy Analysis

**🎯 Primary Purpose**: Real-time strategy analysis and parameter tracking

**⏰ Trigger Mechanism**: 
- Every 5-minute candle close
- Continuous monitoring and analysis

**💼 Execution Type**: 
- Signal generation and parameter tracking
- **NO ORDER PLACEMENT** - observation mode only

**📊 Data Source**: 
- Live candle data from database
- Real-time market data
- Historical data for strategy calculations

**🔄 Processing Flow**:
```
Candle Close → Strategy Engine → Historical Data Fetch → Strategy Processing → Parameter Extraction → Database Storage
```

**🏗️ Core Classes and Methods**:
- `ProductionReadyEngineV2.ProcessStockGroups()` - Main V2 orchestrator
- `StrategyRegistryV2.GetStrategies()` - Strategy management
- `ParameterPersistenceManager.SaveStrategyParameters()` - Parameter storage
- `FirstEntryStrategyV2.Process()` - 1ST_ENTRY strategy
- `TwoThirtyEntryStrategyV2.Process()` - 2_30_ENTRY strategy
- `BBWidthEntryStrategyV2.Process()` - BB_WIDTH_ENTRY strategy

**📈 Output**: Strategy parameters and signals stored in database

---

## 3. Detailed V2 Flow with Classes and Methods

### Phase 1: Initialization Flow

**Entry Point**: `App.NewApp()`
- **Method**: `App.initializeV2Engine()`
- **Class**: `ProductionReadyEngineV2`
- **Method**: `NewProductionReadyEngineV2()`

**Strategy Registration**: `App.registerV2Strategies()`
- **Class**: `StrategyRegistryV2`
- **Method**: `RegisterStrategy()`
- **Strategies Registered**:
  - `MinimalStrategyV2.NewMinimalStrategyV2()`
  - `FirstEntryStrategyV2.NewFirstEntryStrategyV2()`
  - `TwoThirtyEntryStrategyV2.NewTwoThirtyEntryStrategyV2()`
  - `BBWidthEntryStrategyV2.NewBBWidthEntryStrategyV2()`

**Scheduler Integration**: `App.setupScheduler()`
- **Method**: `GroupExecutionScheduler.SetV2EngineInstance()`
- **Interface**: `V2StrategyEngine` (breaks import cycle)
- **Method**: `GroupExecutionScheduler.SetV2Engine()` (enables V2 processing)

### Phase 2: Trigger Flow

**Candle Close Event**: `GroupExecutionScheduler.OnFiveMinClose()`
- **Method**: `GroupExecutionScheduler.processV2Strategies()`
- **Condition**: `v2EngineEnabled` flag
- **Interface Call**: `V2StrategyEngine.ProcessStockGroups()`

### Phase 3: Processing Flow

**Main Engine**: `ProductionReadyEngineV2.ProcessStockGroups()`
- **Method**: `ProductionReadyEngineV2.fetchHistoricalData()`
- **Method**: `ProductionReadyEngineV2.processStockGroupWithStrategies()`

**Historical Data**: `CandleRepository.FindByInstrumentAndTimeRange()`
- **Method**: `ProductionReadyEngineV2.convertCandlesToDataFrame()`
- **DataFrame Creation**: `series.Strings()`, `series.Floats()`, `series.Ints()`

### Phase 4: Strategy Execution Flow

**Strategy Processing**: `ProductionReadyEngineV2.processWithStrategy()`
- **Method**: `StrategyV2.Process()` (interface method)
- **Method**: `ProductionReadyEngineV2.extractParametersFromDataFrame()`

**Individual Strategies**:
- **1ST_ENTRY**: `FirstEntryStrategyV2.Process()`
  - **Methods**: `isMorningRangeCalculationTime()`, `calculateMorningRange()`, `checkEntryConditions()`
- **2_30_ENTRY**: `TwoThirtyEntryStrategyV2.Process()`
  - **Methods**: `isEntryTime()`, `calculateDayRange()`, `checkEntryConditions()`
- **BB_WIDTH_ENTRY**: `BBWidthEntryStrategyV2.Process()`
  - **Methods**: `calculateBollingerBands()`, `calculateBBWidth()`, `isSqueezeDetected()`

### Phase 5: Parameter Persistence Flow

**Parameter Manager**: `ParameterPersistenceManager.SaveStrategyParameters()`
- **Method**: `ParameterPersistenceManager.convertToDomainParameters()`
- **Repository**: `StrategyParametersRepositoryV2.SaveParameters()`
- **Method**: `ParameterPersistenceManager.updateCache()`

**Database Operations**:
- **Table**: `strategy_parameters_v2`
- **Table**: `strategy_state_transitions`
- **Repository**: `postgres.StrategyParametersRepositoryV2`

## 4. V1 vs V2 Critical Differences

### 🎯 **Purpose & Function**
| Aspect | V1 System | V2 System |
|--------|-----------|-----------|
| **Primary Goal** | Execute trades | Analyze strategies |
| **Order Placement** | ✅ Places real orders | ❌ No orders (observation) |
| **Risk Management** | ✅ Full risk calculation | ❌ No risk management |
| **Position Sizing** | ✅ Calculates position size | ❌ No position sizing |

### ⏰ **Timing & Frequency**
| Aspect | V1 System | V2 System |
|--------|-----------|-----------|
| **Trigger Frequency** | 2-3 times per day | Every 5 minutes |
| **Trigger Times** | 9:15 AM, 1:00 PM | Every candle close |
| **Processing Window** | Specific time slots | Continuous monitoring |

### 📊 **Data & Processing**
| Aspect | V1 System | V2 System |
|--------|-----------|-----------|
| **Data Source** | Backtest files | Live candle data |
| **Processing Speed** | ~100-500ms per group | <50ms per group |
| **Memory Usage** | Low (minimal state) | Medium (DataFrames) |
| **Database Load** | Medium (orders) | High (parameters) |

### 🏗️ **Architecture**
| Aspect | V1 System | V2 System |
|--------|-----------|-----------|
| **Design Pattern** | Service-oriented | Strategy pattern |
| **State Management** | Simple parameters | Complex state tracking |
| **Extensibility** | Limited | Highly extensible |
| **Testing** | Integration focused | Unit testable |

## 10. Recent Integration Improvements

### ✅ **Interface-Based Architecture**
- **Problem**: Import cycle between service and strategy/v2 packages
- **Solution**: Created `V2StrategyEngine` interface in service package
- **Benefit**: Clean separation, no circular dependencies

### ✅ **Complete V2 Engine Integration**
- **Problem**: `ProcessStockGroups()` method not being called
- **Solution**: Implemented proper method invocation in `processV2Strategies()`
- **Benefit**: Full V2 engine processing on every candle close

### ✅ **Type Conversion Layer**
- **Problem**: Mismatch between DTO and domain types
- **Solution**: Added `convertResponseToDomainGroup()` method
- **Benefit**: Proper data flow from service layer to V2 engine

### ✅ **Engine Instance Management**
- **Problem**: No way to inject V2 engine into scheduler
- **Solution**: Added `SetV2EngineInstance()` method
- **Benefit**: Proper dependency injection and configuration
